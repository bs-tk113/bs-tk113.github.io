## メインテーマ
AIコーディングエージェント（Claude Code を中心に、Codex CLI・Gemini CLI など）の日本語実践ガイド

## 想定読者
- 主: Claude Code などを使い始めたエンジニア。英語の公式ドキュメントがしんどく、「どう書けば動くか」を日本語で知りたい人
- 副（別シリーズで扱う）: 非エンジニアの業務改善担当。ターミナルの基礎からつまずく層なので、主の読者と同じ記事に混ぜない

## 柱記事（クラスターの中心）候補
1. Claude Code 完全入門（インストール・CLAUDE.md・権限モード）
2. Claude Code の hooks・サブエージェント・MCP を実例で使い分ける
3. AIコーディングCLI 比較（Claude Code / Codex CLI / Gemini CLI）

## 連載候補
- 「AI編集部の制作日誌」: このブログのサブエージェント編集部が、どこで指摘し合い、どう揉めたかの実録（再訪とSNSフォローの理由にする。日向の提案）

## 編集ルール（テーマ選定時のレビューで決定）
- 記事ごとに対象読者を1人に決め、冒頭で「この記事は〇〇な人向け」と書く（日向）
- 冒頭に「確認日」と「対象バージョン」を必ず書く（日向・早瀬）
- 柱記事と周辺記事の半分以上に、この編集部の実際の設定・失敗例・ログといった一次体験を入れる（灰島・日向）。公式の翻訳だけの記事にしない
- 確認日から60日で見直し対象にする。週次レビューでリライト枠を取る（灰島）
- 仕様・版数・モデル名は必ず公式の一次情報で確認する（白石の重点チェック項目）

## テーマの当たり外れの判定（灰島の仮置き。確度: 低。初回の週次レビューで見直す）
- クラスター10本の公開後から判定する
- 30日: インデックス率80%以上、表示回数が出ている記事が半数以上
- 60日: 週の表示回数100以上、11〜30位の記事が3本以上
- 90日: 週のクリック10以上、平均掲載順位30位以内。届かなければピボットか、案B（スプレッドシート＋GAS）の追加を検討
