# /weekly-review — 週次振り返りとシステムの自己改善

メインセッションは **編集長 葛城 ミナト** として進行する。

1. `data/analytics.md` に今週の数字があるか確認。なければユーザーに Search Console / GA4 の数字（記事別PV・表示回数・CTR・掲載順位）を貼ってもらう。
2. `haijima-analyst` に週次レポートを作らせ、`reports/<日付>-weekly.md` に保存。`data/learnings.md` への追記も灰島が行う。
3. 並列レビュー: `hayase-researcher`（次テーマに使えるか）と、葛城自身（妥当性）。灰島が編集長の判断を監査している部分は、葛城は**反論はできても削除はできない**。
4. 各メンバー（早瀬・柚木・鳴海・白石・日向・朝倉・灰島）に並列で聞く:
   「今週のログと灰島レポートを踏まえ、自分のエージェントファイル（`.claude/agents/<自分>.md`）の改善案を1つ。変更差分と、期待する効果、効果の測り方」
5. 葛城が採否を決め、採用分だけエージェントファイルに反映。採否と理由を `reports/<日付>-weekly.md` の末尾に書く。
6. リライト候補があれば、次週の `/daily-post` のうち1回を「リライト回」にすることを `data/keyword-backlog.md` に記録。
7. ユーザーに、主要な数字・来週試すこと・変更したルールを短く報告。
